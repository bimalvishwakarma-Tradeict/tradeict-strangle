S006 protection strike selection bug — DIAGNOSIS
================================================
Date: 2026-09-20
File: backtest/strategies/s006_theta_harvest/strategy.py
Function: S006ThetaHarvestStrategy.build_basket

ROOT CAUSE
----------
0DTE protection strikes are chosen with absolute-distance nearest-neighbor
fallback. There is NO requirement that the short strike exists exactly on the
0DTE chain, and NO OTM / same-strike sanity check before entry.

RELEVANT LINES (build_basket)
-----------------------------

439-444  Comment + target setup:
         "# offset applied OTM-ward: call +po, put -po when po>0; if po==0 same strikes"
         When protection_offset == 0 (default):
             pc_target, pp_target = sc_k, sp_k   # copy short call/put strikes
445-446  THE FALLBACK (bug path):
             pc_k = self._nearest_strike(sorted(c_by_l), pc_target)
             pp_k = self._nearest_strike(sorted(p_by_l), pp_target)
264-267  _nearest_strike definition:
             return min(strikes, key=lambda k: (abs(k - target), k))
         -> always returns SOME strike if the chain is non-empty
         -> never returns None for "missing exact strike"
         -> ignores moneyness (ITM vs OTM)
         -> call and put independently can snap to the SAME edge strike

WHAT HAPPENS WHEN SHORT STRIKE IS ABSENT FROM 0DTE CHAIN
--------------------------------------------------------
1. Shorts are picked on the N-DTE chain (short_dte, default 1) via
   _pick_premium_matched_strangle (lines 417-425). Those strikes are often
   outside the 0DTE listed range for that morning.
2. Protection targets = those short strikes (po=0).
3. Exact membership is NEVER checked (no "if sc_k in c_by_l").
4. _nearest_strike silently snaps each target to the closest listed 0DTE
   strike of that option type — usually the chain EDGE when the short is
   far OTM relative to what 0DTE lists.
5. Basket is entered with whatever snapped strikes + marks; no skip.

WHAT IS NOT BROKEN
------------------
- Short-leg selection on N-DTE chain looks correct (OTM call/put).
- Protection expiry / expire-at-cutoff path is unrelated.
- No alternate fallback after _nearest_strike — that IS the only path.

CONCLUSION
----------
Bug = silent nearest-strike fallback at strategy.py:445-446 with no
exact-match or OTM guards. Fix path (next steps): measure exact-strike
hit rate + OTM gaps; hard-skip ITM / same-strike / short-ITM baskets;
do NOT invent a new strike fallback until hit-rate data is in.
